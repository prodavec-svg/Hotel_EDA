# Hotel Booking EDA

Исследовательский анализ бронирований городского и курортного отелей: спрос, сезонность, отмены и незаезды, длительность бронирований, ADR, клиенты и каналы продаж.

Проект выполнен для портфолио и практики самостоятельного написания аналитического кода на Python. Его цель — получить обоснованные бизнес-выводы и рекомендации. Подготовка модели машинного обучения не входит в текущую задачу.

## Данные и исследовательские вопросы

Используется набор **Hotel Booking Demand**: 119 390 записей бронирований двух отелей с предполагаемыми датами заезда с 1 июля 2015 года по 31 августа 2017 года. Для помесячного сравнения выбран полный 2016 год, чтобы не смешивать полные и неполные годы.

Набор для автоматической загрузки: [`jessemostipak/hotel-booking-demand`](https://www.kaggle.com/datasets/jessemostipak/hotel-booking-demand). Описание полей и исходного исследования: [Hotel booking demand datasets](https://pmc.ncbi.nlm.nih.gov/articles/PMC6297060/).

Основные вопросы:

- Как различаются объём и сезонность бронирований двух отелей?
- Чем отличаются длительность завершённых бронирований и ставки ADR?
- Как доля отмен и незаездов связана со сроком до заезда, сегментом и депозитом?
- Какие страны и каналы формируют структуру бронирований?
- Как отличаются бронирования с признаком повторного гостя?
- Насколько итоговые показатели чувствительны к полным совпадениям строк?

## Основные результаты

Во всех парных значениях ниже первым указан City Hotel, вторым — Resort Hotel.

| Направление | Результат | Практический смысл |
| --- | --- | --- |
| Объём и длительность | 79 330 и 40 060 бронирований; средняя длительность завершённых бронирований с положительным числом ночей — 2,94 и 4,20 ночи | Число бронирований и число ночей нужно рассматривать отдельно: структура спроса различается |
| Отмены и незаезды | 41,73% и 27,76%; доля увеличивается в выбранных интервалах `lead_time` | Общая доля скрывает различия между сроками до заезда и сегментами |
| Сезонность ставок | В 2016 году медианный ADR Resort Hotel — 194 в августе и 44 в январе; максимум всех бронирований обоих отелей — октябрь | Максимумы ставок и числа бронирований не совпадают; ценовую стратегию нужно проверять отдельно |
| Каналы | `TA/TO` даёт 86,91% и 72,20% бронирований; у `Direct` ниже доля отмен и незаездов | Для выбора каналов нужны также комиссии и затраты на привлечение |
| Повторные гости | Доля отмен и незаездов — 21,70% и 6,24%; длительность и ADR также ниже | Предложения повторным гостям стоит проверять с учётом коротких поездок и их экономики |
| Чувствительность к совпадениям | После условного сохранения одного экземпляра каждой полностью совпадающей строки доли отмен и незаездов — 30,04% и 23,48% | Порядок отелей сохраняется, но величина разрыва зависит от правила подсчёта |

ADR в ценовых сравнениях рассчитан для записей со статусом `Check-Out`, положительным ADR и положительным числом ночей. Каждый ряд имеет одинаковый вес; показатель не является средним по проданным номеро-ночам.

В конце ноутбука приведены рекомендации для бизнеса: проверка учёта и платежей, работа с групповыми заказами, экономика каналов, сезонные цены, повторные гости и географические рынки. Для каждой указаны необходимые дополнительные данные и условия проверки эффекта.

## Методология и ограничения

- Одна строка рассматривается как запись бронирования, а не уникальный клиент. Исходные строки сохраняются.
- Полные совпадения не удаляются автоматически: без идентификаторов нельзя доказать, что это ошибки учёта. Условное удаление используется только для проверки чувствительности общих долей отмен.
- `is_canceled = 1` включает отмены и незаезды; в тексте это указано явно.
- Пропуски и необычные значения исследуются перед расчётами. Для разных вопросов применяются соответствующие фильтры, а не единая «очищенная» таблица с удалением всех подозрительных записей.
- Для анализа проживания с ночёвкой исключаются записи с нулём ночей. Отрицательный ADR исключается из расчётов ставок; нулевые ставки рассматриваются отдельно.
- Число бронирований не является загрузкой отеля. Для загрузки нужен доступный номерной фонд, для прибыли — поступления и затраты. ADR сам по себе не показывает выручку или прибыль.
- Наблюдаемые связи не доказывают причинность. Буквенные типы номеров нельзя считать сопоставимыми категориями между отелями без дополнительного описания.
- Исторические данные 2015–2017 годов требуют проверки на актуальной выборке перед применением рекомендаций сегодня.

## Запуск

Проверенное окружение: **Python 3.13.13**, pandas 3.0.5, seaborn 0.13.2, matplotlib 3.10.8, kagglehub 1.0.2, IPython 9.16.1 и ipykernel 7.3.0. Версии зафиксированы в `requirements.txt`; JupyterLab указан как интерфейс запуска отдельно.

Создайте отдельное окружение. Например, с Conda:

```bash
conda create -n hotel-eda python=3.13.13
conda activate hotel-eda
python -m pip install -r requirements.txt
python -m ipykernel install --user --name hotel-eda --display-name "Python (hotel-eda)"
```

Из корня проекта запустите:

```bash
python -m jupyterlab
```

Откройте `notebooks/01_hotel_eda.ipynb`, выберите ядро **Python (hotel-eda)** и выполните ячейки по порядку. Также можно открыть ноутбук в PyCharm или VS Code, выбрав интерпретатор этого окружения. Путь к CSV определяется при запуске из корня проекта или папки `notebooks/`.

Если `data/raw/hotel_bookings.csv` отсутствует, ноутбук загружает его через `kagglehub`; нужен доступ к интернету и Kaggle. Альтернативный путь — скачать CSV из указанного набора и поместить его в `data/raw/`. С существующим локальным CSV анализ не требует загрузки данных.

Исходный датасет, настройки IDE и локальная конфигурация исключены из Git. Сохранённые таблицы и графики находятся в самом ноутбуке.
